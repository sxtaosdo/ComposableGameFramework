# 通用编码规范

状态: Accepted

## 适用范围

适用于所有语言与引擎。编码前必须从目标产品的 Accepted 文档确认技术栈，再读取对应引擎规范；未指定时不得自行选择。

## 编码前

- 明确假设；歧义、矛盾或不确定项先澄清。
- 先定义可观察的成功标准和验证方式。
- 优先最简单、最小且可验证的实现。

## 实现原则

- 精准修改任务范围，不顺手重构、格式化或清理相邻代码。
- 匹配现有风格；删除仅因本次修改产生的死导入或变量。
- 不为一次性需求创建抽象层，不提前增加配置与扩展点。
- 小函数、低耦合、组合优于继承，避免单例泛滥。
- 类名使用大驼峰；变量名与文件名使用小驼峰。
- 类文件原则上不超过 200 行，最多不超过 500 行；完整实现无需机械拆分。

## 禁止事项

- 复杂热更新体系、提前优化、无限抽象。
- 跨模块污染和无关修改。
